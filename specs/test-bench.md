# Spec: test bench

## Responsibility

The test bench is the only sanctioned way to validate compiler changes. It runs two pillars of tests:

1. **Correctness** — for each test program, compile with `pyx86`, then differential-test against CPython on a generated input set. Mismatches are failures.
2. **Performance** — for each benchmark, compile both a Python and an equivalent Rust implementation, measure CPU time, assert the Python/Rust ratio is below a configured threshold.

It is invoked as a single Rust binary (`pyx86-bench`), parallelizes work across configurable cores, and supports tier-filtered runs so cheap tiers can gate expensive ones.

## CLI

```
pyx86-bench [--tier=N] [--jobs=Q] [--filter=GLOB] \
            [--corpus-root=PATH] [--compiler=CMD] \
            [--json-out=PATH] [--keep-tmp]
```

| Flag | Default | Meaning |
|---|---|---|
| `--tier` | `1` | Run all tests at tier ≤ N. Tiers are 1 (unit, 3 s budget), 2 (smoke, 30 s), 3 (medium, 5 min), 4 (large, 1 hr). |
| `--jobs` | `num_cpus` | Parallel workers. Each test runs in its own subprocess. |
| `--filter` | `**` | Glob applied to test program names. |
| `--corpus-root` | `tests/` | Directory containing `correctness/` and `performance/` subdirs. |
| `--compiler` | `cargo run -q -p pyx86 --release --` | How to invoke the compiler. Bench passes the .py path and an `-o` output path. |
| `--json-out` | none | If set, write structured results to this file. |
| `--keep-tmp` | false | Keep the per-test scratch directory for inspection. |

Exit code: 0 if all tests pass, 1 otherwise.

## Test corpus layout

### Correctness — `tests/correctness/<program-name>/`

- `program.py` — the program under test. Must define `def main(...)`. The bench generates inputs matching the strategy and calls `main(*args)`, comparing the printed `repr(...)` of the return value across CPython and the compiled binary.
- `tier.toml` — declares `tier = N` (1–4) and per-tier `iterations` map:
  ```toml
  tier = 1
  iterations = { tier1 = 1, tier2 = 10, tier3 = 1000, tier4 = 1_000_000 }
  ```
  If a key for the requested tier is absent the test is skipped at that tier.
- `strategy.toml` — *optional*. Describes input shape for fuzzing. Omit when `main()` takes no args:
  ```toml
  [[arg]]
  type = "i64"
  range = [-1_000_000, 1_000_000]
  ```
  Strategies are kept TOML, not Python, so the Rust bench can read them directly without embedding a Python interpreter. Currently supported types: **`i64`** (requires `range = [lo, hi]`, inclusive). Container/aggregate types (e.g. `list[i64]`) come in later slices when the compiler supports them.

### Performance — `tests/performance/<benchmark-name>/`

- `program.py` — Python implementation
- `program.rs` — equivalent Rust (idiomatic, not micro-optimized)
- `bench.toml`:
  ```toml
  tier = 3
  warmup = 5
  iterations = 50
  max_ratio = 2.0   # python_time / rust_time
  ```
- Bench inputs are generated by a `[[input]]` section (same shape as `strategy.toml`).

## Procedure — correctness

For each program in `tests/correctness/` matching the filter and tier:

1. Compile to a scratch dir: invoke `--compiler` with `<scratch>/<name>.elf` as the output. Capture stderr; non-zero exit = compile failure.
2. Read `strategy.toml` (if present); generate per-tier iterations of inputs via `rand` seeded deterministically by the test name (override with `--seed`). With no strategy, generate one empty input set and run a single iteration.
3. For each input:
   - **Reference**: format the args as Python int literals into `python3 -c "import sys; sys.path.insert(0, R'<dir>'); from program import main; print(repr(main(<a>, <b>, ...)))"`. Capture stdout, exit code.
   - **Subject**: run `<scratch>/<name>.elf` with the same args as positional argv strings. Capture stdout, exit code.
   - Compare. Mismatch ⇒ stop iterating, record the input + expected + actual on the test result.

CPython and the compiled binary are expected to print exactly the same `repr(...)`-formatted string. Both end with a single newline.

Input shrinking on failure is **not yet implemented** — the bench reports the first failing input as-is. Shrinking lands once false-positive noise warrants it.

## Procedure — performance

For each benchmark in `tests/performance/`:

1. Compile both implementations:
   - Python: invoke `--compiler` to produce `<scratch>/<name>-py.elf`.
   - Rust: `rustc -O <dir>/program.rs -o <scratch>/<name>-rs.elf` (later: `cargo build --release` if the bench grows out of single-file Rust).
2. Generate one input set per the `[[input]]` section.
3. For each implementation: run `warmup` times (discarded), then `iterations` times, recording wall-clock CPU time per run via `clock_gettime(CLOCK_PROCESS_CPUTIME_ID)`.
4. Report median Py time / median Rs time = ratio. Fail if `ratio > max_ratio`.

## Parallelism

Each test program is independent. Work distributed via a `rayon` thread pool sized to `--jobs`. Each worker compiles, runs, diffs, then writes its result to a shared `Vec<TestResult>` behind a `Mutex` (write contention is negligible vs the time spent compiling).

Human-readable summary on stdout:

```

  ✗ add_two_ints        100 inputs, FAIL on (a=0, b=-1): expected '-1', got '4294967295'
performance:
  fib_iter_30           py 4.2 ms / rs 3.9 ms   ratio 1.08x  (limit 1.5x)  ✓
2 of 3 tests passed (1 failed). 0.42s wall.
```

## Tier promotion rule (operational)

Future Claude sessions and the developer follow:
- Tier 1 (3 s) after every meaningful edit.
- Tier 2 (30 s) before each commit.
- Tier 3 (5 min) before pushing.
- Tier 4 (1 hr) **sparingly** — only after several major features have landed, or before a release. Do not run per-PR.

A change that fails tier N is not promoted to tier N+1.

## Out of scope for v1 of the bench

These are listed so future contributors don't accidentally re-add them under the same names:

- Network-bound tests, fixtures, or mocks.
- Coverage measurement.
- Mutation testing.
- Snapshot comparison of compiler IR (covered by per-pass unit tests inside `pyx86`, not the differential bench).
- Cross-platform testing — Linux x86-64 only in v1.

## Implementation notes

- **Compiler stub**: when `pyx86` does not yet support a feature used by a test, the compile step fails with a non-zero exit and a clear stderr message. The bench surfaces this as "compile failed: <stderr>" rather than a diff mismatch.
- **CPython version**: the bench shells out to whatever `python3` resolves to (set by pyenv shim). The repo targets Python 3.12+; tests using newer syntax should declare a min version in `tier.toml` (`min_python = "3.12"`) so the bench can skip them on older interpreters.
- **No `unsafe`** in bench code — performance of the bench itself is not load-bearing.
